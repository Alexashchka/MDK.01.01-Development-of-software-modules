Экзамен 2 (пробный вариант)

Постановка задачи


Разработать REST API, который выполняет базовые функции CRUD (cсоздание, чтение, изменение, удаление).

В качестве базы данных использовать MySQL или MSSQL, при работе желательно использовать EntityFramework.

Для каждой CRUD операции, разработать конечную точку, соответствующего типа:
1) Добавление – POST;
2) Чтение – GET;
3) Изменение – PUT;
4) Удаление – DELETE;

Для запроса GET, предусмотреть возможность сортировки и фильтрации отображаемых данных посредством указания параметров.

Для каждого запроса, предусмотреть возвращаемые коды:
1) 200 – запрос успешно выполнен;
2) 201 – запрос успешно выполнен, в результате был создан новый ресурс;
3) 400 – плохой запрос (не правильно указанные данные)
4) 401 – пользователь не авторизован
5) 403 – пользователь не имеет доступа к ресурсу
6) 500 – ошибка сервера
Кроме кода, необходимо чётко и понятно указать причину, возникновения ошибки.
Например: 400 – плохой запрос (Поле login, имеет неверный формат).

Для разработанного RestAPI, реализовать документацию SWAGGER. К каждому запросу, параметру, коду ошибке, возвращаемым данным предоставить комментарии на русском языке.

Для запросов типа POST, PUT, DELETE предусмотреть указание токена в заголовке запроса, полученного при авторизации пользователя (отдельный запрос), с разграничением доступа:
Логин и пароль:
Admin – администратор системы (может добавлять, изменять и удалять)
User – пользователь системы (может добавлять и изменять)

Все вводимые значения необходимо проверять на корректность ввода, например:
- дата и время – на дату и время;
- длительность – на ввод только чисел;
- ФИО на ввод только текстовых значений;
- номер телефона на соответчике маски;
- и т.д.
в противном случае выводить ошибку 400 – плохой запрос.
